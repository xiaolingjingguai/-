# HJ 169 风险计算器 — 软件授权（许可）机制说明

本程序内置“机器绑定 + 离线授权”机制，使软件只能在你（作者）签发授权的机器上运行，
用于把软件只发给指定用户使用。

## 一、原理（一句话）

- 每台电脑有一个唯一**机器码**（指纹）。
- 你用**只在你手上的私钥**，为某台机器的机器码签发一个**授权文件 `license.key`**。
- 程序启动时用**内置的公钥**验证 `license.key`：签名正确、机器码匹配、未过期才放行。
- 用户无法伪造授权文件（没有你的私钥），也不能把授权文件拷到别的机器上用（机器码不符）。
- 全程离线，不联网激活。

采用 Ed25519 非对称签名。程序内的验证为纯 Python 实现，不增加打包依赖；
签发工具使用 `cryptography` 库。

## 二、作者首次准备（只做一次）

> 仓库里自带一套**演示密钥**，开箱即可试用全流程；但演示私钥是公开的，**正式对外分发前务必换成你自己的密钥**，否则他人可伪造授权。

1. 生成你自己的密钥对（**双击 `HJ169_密钥生成器.exe`**，或运行脚本）：
   ```
   python tools/make_keys.py
   ```
   - EXE 形态：私钥生成在 EXE 同目录的 `keys\author_private.pem`，公钥写入同目录 `公钥_PUBLIC_KEY.txt`。脚本形态私钥在 `tools/keys/author_private.pem`（已在 `.gitignore`，不会入库）。
     **请把它离线备份、妥善保管，切勿上传仓库或随程序分发。私钥丢失＝无法再签发新授权；私钥泄露＝授权体系失效。**
   - 屏幕会打印一行 `PUBLIC_KEY_HEX = "..."`。
2. 用这行替换 `app/license_verify.py` 顶部的 `PUBLIC_KEY_HEX` 常量。
3. 重新打包程序（推送到 `claude/**` 或 `main` 分支会自动在 GitHub Actions 上构建 Windows EXE；
   或本地用 `packaging` 里的方式/工作流中的 PyInstaller 命令打包）。

此后，所有授权都用你这把私钥签发，只有装了对应公钥的这一版程序能验证通过。

## 三、给指定用户授权的流程

1. **用户取机器码**：用户运行程序，未授权时会弹出窗口显示本机“机器码”（如 `A1B2-C3D4-E5F6-7890`），
   点“复制机器码”发给你。
2. **你签发授权**，二选一：
   - 图形界面（推荐，**双击 `HJ169_授权码生成器.exe`**，或运行脚本）：
     ```
     python tools/license_issuer.py
     ```
     填入机器码、授权给（名称/单位，可选）、到期日（**留空＝默认一年有效期**；填“永久”＝永久；也可填具体日期），选择你的私钥，点“签发 license.key”。
   - 命令行（便于批量）：
     ```
     python tools/license_issuer.py sign --machine A1B2-C3D4-E5F6-7890 \
            --name "某某环保公司" --expiry 2027-12-31 \
            --key tools/keys/author_private.pem --out license.key
     ```
     `--expiry` 省略即默认一年有效期（自签发日起）；加 `--permanent` 为永久授权；也可用 `--expiry YYYY-MM-DD` 指定任意到期日。
3. **发回用户**：把生成的 `license.key` 发给该用户。
4. **用户启用**：把 `license.key` 放到程序 `HJ169_Calculator.exe` 的**同一目录**，重新启动即可使用。

到期日到了之后程序会拒绝启动并提示已过期；续期时为同一机器码重新签发一个新 `license.key` 覆盖即可。

## 四、安全边界（请务必知悉，不夸大）

- 本机制能有效阻止**普通用户的私自传播、换机使用、改日期绕过有效期**。
- 但 Python/PyInstaller 打包的程序**可被专业人员逆向**：有能力者可能删除校验逻辑、或替换内置公钥后自行重打包。
  因此本机制**不能抵御专业级破解**。
- 如需更强保护，建议叠加**代码混淆/加密**：
  - 推荐 **PyArmor**（成熟商用方案，支持字节码混淆 + 运行时保护，且本身自带机器绑定许可功能，可与本机制二选一或叠加）。
  - 典型做法：`pyarmor gen --output dist_obf app/hj169_gui.py ...` 后再用 PyInstaller 打包混淆产物；
    或直接用 PyArmor 的 `--pack` 一步打包。具体命令随 PyArmor 版本变化，使用前请查其现行文档并评估授权成本。
- 结论：**“本授权机制（防传播/绑定/到期）+ PyArmor（防逆向）”** 组合，可在不联网的前提下达到对自有软件较实用的保护强度。

## 五、相关文件

- `app/license_verify.py`：程序内置校验（含内置公钥、机器码计算、启动门禁弹窗）。
- `app/_ed25519_pure.py`：纯 Python 的 Ed25519 验证（随程序打包，无额外依赖）。
- `tools/make_keys.py`：生成作者密钥对。
- `tools/license_issuer.py`：授权码生成器（GUI + 命令行）。
- `tools/keys_demo/private_demo.pem`：**演示私钥**（仅供试用，勿用于正式分发）。
- `tests/test_license.py`：许可机制自测。
